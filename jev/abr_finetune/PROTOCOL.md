# Kev-4B ABR 监督微调协议 v2（原始采集记录隔离）

从本地发布版 Kev-4B v1.0 的 LoRA 和 pointer head 继续训练，不从裸 Qwen 随机初始化，不进行全参数训练。基座与发布模型文件保持原样，新检查点保存到本目录。

固定原零样本评测的状态表达、提示词、候选描述、六档动作、video1 和仿真器。训练与评测的唯一策略变更是模型权重；训练样本随机打乱候选顺序。训练期间关闭插入“其他选项”、删除正确选项等不适用于 ABR 的增强。

监督数据仅来自官方 NetLLM FCC-train 目录（原 235 条，包含 FCC 与 Norway 日志）。按 FCC 原始采集 ID 和 Norway 完整日志标识隔离训练/验证/测试，排除同一原始记录的不同窗口；还排除完全重复的数值轨迹及与验证集重复的训练状态。每条保留轨迹生成 MPC、BBA、探索行为三种 rollout，所有状态的标签均由 RobustMPC-6 在该状态下规划产生；探索行为以 30% 概率随机动作，标签仍来自专家。记录轨迹和状态来源。相同训练状态如果标签冲突则剔除，不做多数票拟合。

生成完整监督数据池后，固定 seed=666 选择最多 8000 个不重复状态，优先保证每个动作最多 200 个基础样本，再从剩余池均匀抽样补足。不会使用 FCC-test、HSR、Oboe 或 Norway3G 的动作、QoE、标签进行训练或选参。同一地区或采集项目仍可能出现在不同 split；source_overlap.json 报告从文件名推断的原始记录隔离及来源组成。

FCC-valid（原 150 条）用于验证，排除与测试同源记录及完全重复数值轨迹后保留 30 条、2 个采集 ID。以固定哈希排序，最多挑选 40 条（本轮为全部 30 条），选取闭环平均 QoE 最高的检查点；最终对选定模型运行完整清洁验证集和四组原测试集。验证来源数少，不能作为广泛泛化证据。保留每轮检查点，不根据测试结果调整学习率、轮数或提示词。

计划训练两轮，lr=2e-5，LoRA rank 与发布模型一致（16），batch=2、accum=8，BF16 autocast、FP32 冻结基座和主参数，gradient checkpointing。先用少量真实样本验证前向、反向、优化与存盘；如果显存不足只调整 batch/accum 保持有效 batch=16。用官方训练器，额外包装仅用于保存每轮检查点。训练可使用 FLA/Triton 加速；所有闭环模型评测继续使用原推理环境，避免更换推理内核影响前后比较。

监督模仿并不保证超过专家。主结论依赖闭环 QoE、码率、卡顿和切换，不仅是动作准确率。模型输出概率本轮不作任务校准，不能作为已经校准的 ABR 置信度。QoE 沿用原模拟口径，不扣减推理等待时间。
