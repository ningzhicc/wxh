# Kev ABR 延长训练与逐轮早停协议

本轮沿用已冻结的 source-isolated 数据：55 条训练轨迹、7,224 个唯一状态；清洁验证 30 条、两个 FCC 采集 ID。训练数据、状态、标签、六档候选、提示词、视频、仿真器和测试起点均不改变。

预估累计六轮左右可能进入验证收益平台，实际最佳轮数由验证决定，最多累计十轮。既有第一、二轮检查点均保留为候选；后续权重从 sft_v3/epoch_02 开始，最多再训练八轮。

上一阶段没有保存优化器状态，因此本轮开始时重建一次 AdamW 与 OneCycle 学习率调度，峰值从 2e-5 降到 1e-5。这是权重继续训练的新优化阶段，不能称为对旧优化器状态的精确恢复。本阶段各轮之间保留优化器、调度器、随机数和数据顺序，并保存可用于下一轮恢复的训练状态。

冻结基座，继续训练既有 rank-16 LoRA 和 256 维 pointer head，batch=2、accum=8、有效 batch=16、weight_decay=0.01、BF16 autocast、FP32 基座和主参数、gradient checkpointing，seed=666。继续复用官方 DecisionModel、training_requests、microbatch_plan、encode_batch、batch_loss、梯度裁剪和 checkpoint 格式，新增控制循环用于逐轮验证、保存状态和早停。

每轮完成后保存模型，将训练模型和 Adam 矩暂存到 CPU，释放 GPU，再用原推理环境启动该轮检查点进行闭环验证。验证后停止服务，将原训练对象与优化器移回 GPU；优化器参数对象及状态保持连续。验证过程中不更新参数。

每个候选用固定 30 条验证轨迹评估两次；两次会话平均 QoE 的均值为选模分数。复跑用于减弱既有 BF16/动态批处理引起的小幅波动，不是新增独立验证数据。旧第一、二轮也按相同规则重新计分。

严格保留观测到的最高验证均值检查点。实质改善阈值为每块 QoE +0.005；相对最近实质改善的分数，连续三轮未超过该阈值，且累计至少训练六轮时，停止后续优化。若达到十轮上限则停止并记录上限原因；上限停止不等于证明收敛。最后服务回切到验证最佳检查点，可能早于最后训练轮。

四个测试集不参与梯度、轮数选择、学习率选择或早停。选模冻结后才评测，比较既有两轮模型、原发布版及 BBA/Throughput/RobustMPC。这些是已经查看过的同一测试集上的后续比较，不宣称它们是新的未见确认数据。所有原运行、模型与报告保留，不覆盖。

正式训练前用少量真实样本验证前后两次参数更新、CPU/GPU 转移、优化器连续性、存盘与原推理环境验证；探针模型不进入正式候选。
