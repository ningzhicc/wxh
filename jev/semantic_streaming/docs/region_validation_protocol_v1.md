# 区域定位与端到端验收口径 v1

本协议保留既有失败门槛，区分四种证据，不把扩大编码保护区算成API定位改善。

1. **是否命中所问对象。** 非空框只能说明接口输出了坐标，还须检查框是否对应目标，是否框到手臂、水印、相邻物品等干扰区域。碗的9秒帧就是非空但框错对象。
2. **API逐帧空间覆盖。** 有对齐可靠的目标掩码时，按同一原生帧比较API框与掩码。原先API平均覆盖至少80%的门槛不改；碗58.7%仍未通过。掩码帧号存在全局疑点时同时保留局部目视对应、原帧哈希和偏移敏感性，不选择最有利偏移抬高分数。
3. **编码实际保护范围。** 单独记录采样框静态并集、8像素padding、宏块对齐后的矩形，并记录所选qoffset。碗83.0%是这个范围的诊断覆盖率；qoffset=0的启动块不额外区分ROI质量。此指标不替代API指标。
4. **接收端是否保留答案证据。** 原视频、带宽接收视频、Kev接收视频均用完整画面重复开放问答3次。记录全部原始回答、正确次数和相同请求是否一致。首帧问题只允许frame_index=0作依据；之后的倒计时读数不能代替。原图答错、读不清或定位失败均保留。

文字、数字等任务需要辨读的是文字区域；未提供密集人工掩码时不宣称获得了定量空间准确率。现有助手标记的seed框只作离线审查线索，不输入定位或Kev，也不冒充人工GT。颜色任务的局部颜色区域可能足以答题，仍须独立报告整物体掩码覆盖，不能事后重定义原门槛。

本轮三个案例在新API调用前固定为衣服文字、首帧计时器、中央黄色出租车车牌；它们是已用开发视频，不能据此报告独立泛化效果。单个问题原图/接收图各3次全对仅作为开发诊断，不把三次重复当成三个视频样本，也不自动批准训练数据。

碗的逐帧实图与判断见 [几何审查](../runs/bowl_geometry_review_v1/REPORT.md)。三案例操作与结果见 [完整流程回归](clear_task_regression3_v1.md)。
