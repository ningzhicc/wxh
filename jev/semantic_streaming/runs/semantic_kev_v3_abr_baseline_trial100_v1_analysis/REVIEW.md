# v3 ABR 初始化100步试训分析

结论：训练与闭环评估完整结束；当前 Kev 的平均综合收益低于两种简单策略。画质较高，但下载过大、卡顿偏多。

| 策略 | 平均每场景奖励（越高越好） | 平均每场景卡顿秒（不含起播） | 平均证据 PSNR dB |
|---|---:|---:|---:|
| cheapest | 36.24 | 0.455 | 23.35 |
| bandwidth | 50.84 | 3.354 | 37.01 |
| model | 9.99 | 13.913 | 39.66 |

- 从原始 merina656_baseline_seed666/checkpoints/epoch_08 载入，100次更新、800条记录曝光，耗时9.56分钟。无拒绝／截断记录。尚未完成一轮4560条训练数据。
- 验证为4条网络轨迹×5起点，20个场景×20片段；所有策略起播规则相同。新增模型推理380次，起播20次不由模型选档。
- 模型有77次卡顿选择，其中52次在当时同一游标下存在实际不会卡顿的候选；该判断使用离线未来回放。
- 另有25次选择，按已知历史带宽估计就无法在当前缓冲内完成，而存在估计可以及时完成的其他候选。
- 模型相对带宽策略在20场景中赢6场、输14场，平均回报差-40.85。
- 模型决策时的缓冲中位数6.69秒，带宽策略为13.77秒。与更激进选择、后续缓冲减少的现象一致，不能仅据此认定单一因果。
- 训练标签仍是一步真实回放最优：3364/4560（73.77%）所选下载耗时超过该片段播放时长。单次可用缓冲容许，但一步目标没有显式计入反复消耗缓冲的后续代价。

建议先加入基于历史带宽和可持续传输预算的候选约束，并改进考虑后续缓冲的离线监督目标；再考虑对严重决策损失加权。随后在统一闭环条件下检查多个训练步数的检查点，而非只看分类 loss 或直接延长当前训练。

本次分析仅使用已有文件，未启动新训练／GPU推理／API调用。没有未微调 ABR 初始化模型在 v3 上的对照，不把问题归因于 ABR 初始化本身。新旧 v2/v3 奖励尺度不同，不直接跨版本比较奖励。
