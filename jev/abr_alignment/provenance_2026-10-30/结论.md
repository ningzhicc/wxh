# DyLas 论文训练池追溯结论

## 当前结论

**没有在本次检查的本地文件和 Git 历史中找回论文所述的600条、DP/GENET/Comyco=300/150/150经验池。不能把任何现有文件认证为这份论文原始池。**

但找到了新的、与用户目标直接相关的证据：**本地保留的一组播放结果，在“去掉首片、保留末片，跨网络记录使用样本标准差”的统计下，四个均值和标准差均与用户截图最后一行按两位小数完全一致。**其清单标记为v4、rank128、seed666。

结合历史脚本显式指定的经验池、旧训练日志的2055个训练窗口以及实际数据加载器核对，**`merina_merged_logits.pkl`（656条、30,832步）是追溯本地这套v4结果最有力的训练池候选**。这是由多项证据支持的关联推断；缺少当次训练池哈希和结果到精确checkpoint的唯一绑定，仍不能认证它就是论文原始600条池，也不能排除截图来自另一批数值恰好相同的实验。

- 13份当前训练控制台日志、当前和Git保留的v4脚本、当前和历史数据加载器、结果清单、275份已有播放日志。

没有恢复文件到原仓库，没有修改旧数据、权重或冻结协议，没有启动训练或重新跑模型。所有新增文件只在当前工作区的 `jev/abr_alignment` 下。

完整数量、哈希和每局数值指纹见 `inventory.json`；原始证据副本位于 `source_snapshots/` 与 `git_source_snapshots/`。原始训练池类别和网络来源不能单凭文件名判定。

**这也修正了此前的比较假设：如果目标是匹配截图这组数值，就应明确保留“去首片、保留末片、ddof=1”这一统计结果。** 当前common_v1主指标是去首尾且报告总体SD；它仍可用于双方同协议比较，但不能直接拿其主指标和截图相减。其辅助均值去首片，可提供另一条核对线索。截图数值一致不代表已经复现论文文字所述的100次会话、五个训练种子汇总或原始600条池。

结果清单没有训练池哈希和精确checkpoint路径，训练目录命名又省略了经验池文件名。这是目前不能把“结果清单→某个权重→某份池”锁成完整证据链的原因。

## 4. 对下一步的约束

1. **严格复现论文600条方案：尚缺原始文件或可靠生成清单。** 需要包含教师组成、逐局来源和起点／随机种子的记录，以及对应权重；不能从656条中任取600条替代。
2. **针对本地截图所对应数值开展公平实验：656池是优先候选。** 若以此为主线，应明确实验名称为“本地656条共同训练池比较”，让DyLas和Kev用相同基础经验重新训练，并采用独立验证集选模。这样得到的证据比给旧权重补一个未经证实的训练来源更可靠。
3. 656池只保存states/actions/rewards/dones/teacher_logits，没有逐局网络来源和教师身份。原始候选代价表示可以从已有状态构造；候选收益差标签仍需补齐可重放的完整环境状态，不能根据6×6观测伪造六档真实后果。
4. 本次没有把656池设为已认证论文池，没有修改训练入口或评分协议。若后续决定围绕截图统计建新协议，应创建新版本，同时保留common_v1和旧结果。
